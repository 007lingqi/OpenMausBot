# 钉钉研发助手重设计：实施目标

日期：2026-09-11。原生 Goal 已创建并处于 active；本文是验收与接续记录，不是第二套运行状态。预算：未指定。

## Objective

执行[完整重设计方案](dingtalk-rd-assistant-redesign-20260911.md)，将现有系统升级为一个自然群聊入口、持久事项中心和可验证研发交付流水线。核心结果是需求理解准确、对话接续自然、回复简短可信、测试减少遗漏，主 Agent 可凭有界上下文继续工作。

## Scope 与交付

1. 自然协作：版本化统一回合；事实、假设、问题与冲突；实际送达选项接续；授权项目只读调查；多事项、多意图和自然回复。
2. 研发交付：当前 Spec、受限独立工作区、开发自测、独立 Verifier、程序验收；代码完成、环境应用和通知分别结算。
3. 迁移与运行：副本演练、无副作用影子对照、同事项单写入者、小范围切换；旧任务结清后退出旧编排。
4. 提交实现、自动化回归、真实模型和真实平台试点证据、恢复入口与最终验收记录。逐批交付不缩小整体目标。

## 非目标与约束

- 不要求钉钉文档、表格、附件、DWS 或卡片模板；不删除已有能力和历史。
- 不以 Token 节省降级模型；沿用宿主 OpenCodex / gpt-6-astra / medium 的已授权受限通道，不新增密钥。
- 普通低风险修改在已授权范围内自动完成，不要求用户接受结果。生产、默认分支合并、身份凭据、破坏性及不可逆动作依仓库规则对固定候选请求唯一 Owner 决策；不自动 push。
- 群白名单、真实身份、来源、版本、Owner 控制和 Secret 保护不降级；群聊、引用和项目资料不能授予权限。
- 保存后确认入站；发送检查平台业务响应；未确认的外部效果先对账再重试。
- 保留用户已有改动及未跟踪的 `outputs/`。本次实现不触碰无关支持邮件和账号用量事项。

## Autonomy 与停止条件

用户本轮明确授权生成 Goal 并实施方案。自主完成仓库内实现、隔离自动测试和合格批次本地提交；已授权受限本机模型通道按原对象范围复用。真实外发/部署前核对具体对象、候选与授权，不凭历史笼统“继续”扩大权限。

需要新增付费、凭据/身份变更、生产、默认分支合并、删除或不可逆影响时，仅停止相应步骤并请求唯一 Owner 明确授权；其他安全工作继续。关键不确定项先调查，不凭假设执行。同一失败连续三次停止原路径、留存脱敏证据并重新规划；原生 blocked 状态仅按宿主连续目标轮次规则设置。

## 首批实现与实际证据（2026-09-11）

### 已实现

- 问题区分未回答、部分回答、已解决与更正替代；部分回答必须保留剩余问题，更正替代必须有当前消息引用及本轮新问题，不能消除系统门禁。
- 状态变化由程序生成，和 Spec、澄清及 Outbox 在现有事务中保存为不可变回执；模型不能伪造状态回执或回答人身份。失败、过期和重放不产生新的问题历史。
- 从账本回执重建有界问题上下文：保留全部当前问题及最近 25 个关闭问题；更早记录不删除，校验问题 ID 时仍查询完整历史，避免截断后重新使用已解 ID。
- 不再把“本轮只展示三问”误当成“只允许回答这三问”：较早未解问题的自然回答也能被接收。
- 不添加数据库迁移，不写真实业务数据；旧快照无问题来源时标未知，不补造历史。当前兼容性范围不构成旧二进制可安全回滚/双写的承诺。
